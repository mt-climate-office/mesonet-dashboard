# Fidelity harness

This harness compares the legacy Dash dashboard (`app/mdb`) with the React rewrite (`web/`) using Playwright and Node ESM. It needs no dependencies beyond the `playwright` devDependency already in `web/`.

| Comparison | A (reference) | B | What it proves |
|---|---|---|---|
| `api-parity` | legacy API `mesonet.climate.umt.edu/api/` (with `premade` as prod sends it) | mesonet2 `/api/v2/` | Data/backend differences, with no browser involved |
| `data-parity` | prod legacy `mesonet.climate.umt.edu/dash` | local legacy (shim) on mesonet2 | The same UI on both backends shows the same plotted numbers |
| `ui-latest` | legacy (`--legacy localLegacy` by default, so the data is identical) | new app | Latest Data plots (`gd.data`), axis titles, annotations, sensor shapes, top/bottom card text, network errors |
| `ui-downloader` | legacy | new app | Downloaded CSV: filename, columns, row count, values |
| `ag` | mesonet2 `/derived/{daily,hourly}`, no `premade`, `keep=true`, `alpha=0.23` | new app Ag Tools | Ag values: each derived column is matched to the closest trace, raw or cumulative |

## Run

```sh
cd web
# new app dev server (any port; pass it via NEW_URL)
npx vite --port 5188 --strictPort &
# legacy local (see below), then:
NEW_URL=http://localhost:5188/mesonet-dashboard \
  node scripts/fidelity/run.mjs --compare api-parity,data-parity,ui-latest,ui-downloader,ag \
  [--stations acebozem,lololowr] [--scenarios default,daily] [--out DIR] \
  [--legacy prodLegacy|localLegacy] [--a prodLegacy --b localLegacy] [--concurrency 1] [--headed]
node scripts/fidelity/run.mjs --report-only --out DIR   # rebuild DIR/report.html
```

- **Output.** The default `--out` is the session scratchpad `…/scratchpad/fidelity-out`. Each comparison writes `DIR/<compare>/results.json`, plus `captures/*.json` (the full extracted figures), `shots/*.png` and `files/*.csv`. `DIR/report.html` is a self-contained matrix of scenario × station with expandable details.
- **Exit code.** The run exits non-zero if any item is FAIL or ERROR, so it can serve as the cutover gate.
- **Statuses:**
  - PASS: equal within tolerance (`abs 0.0011`, `rel 2e-4`; override with `FIDELITY_ABS_TOL` / `FIDELITY_REL_TOL`).
  - WARN: only edge points differ (the two sides were captured a few minutes apart), or only label wording differs.
  - FAIL: a trace is missing or extra, or interior values or nulls differ.
  - ERROR: one side failed to load.
- **Browser.** It uses Playwright's bundled Chromium if installed (`npx playwright install chromium`). Otherwise it falls back to the system Chrome (`channel: 'chrome'`). `FIDELITY_CHROMIUM=/path` overrides both.
- **Waits.** The harness never relies on `networkidle`. It waits for specific `.js-plotly-plot` elements with data, then for a re-render (a `gd.data` identity change or a card DOM change), then for a quiet period with no xhr/fetch requests (`TIMEOUTS.settleQuiet`). The A and B captures of one item run in parallel against different servers to reduce time skew. Items run serially by default (`--concurrency 1`).
- **Driving controls.** Legacy controls that are hard to click (dmc DatePicker, MultiSelect, the Downloader station dropdown) are driven through the component's Dash `setProps`, found via the React fiber (`dashSetProps` / `dashGetProps` in `lib/drivers.mjs`).
- **New-app URLs.** New-app deep links are built in `config.mjs#newAppUrl`. Update that one place when the Wave 1a url-state keys change (`vars` → `lv`/`sv`, per-tab `from`/`to`).

## Mobile check

`NEW_URL=... node scripts/fidelity/mobile.mjs [--out DIR] [--station acebozem] [--no-legacy]` screenshots Latest, Current Conditions, Ag (GDD), the Downloader and a malformed-date link (ES-005) at 375 and 768 px. It records horizontal page overflow (scrollWidth > innerWidth, plus the elements responsible) in `DIR/mobile/results.json`. `report.html` shows the results as a `mobile` section.

## Comparator conventions

- Daily x values are normalized to the date (midnight equals date-only). Points that appear on one side only and are null there (gap markers) are ignored.
- `ag` compares only each scenario's derived *output* columns (`outputs` regex). Depth columns match traces by depth (cm→in: 5→2, 10→4, 20→8, 50→20, 91→36, 100→40). The `/derived` `end_time` is sent as end+1 because the new app's range is inclusive.
- Downloader: legacy gets end+1 for the same reason (its filename therefore shows end+1). Ranges end 2 days back, because legacy turns end==today into "now". The start is clamped to `date_installed`. Legacy's unnamed index column is ignored. Extra B columns and case-only boolean differences WARN.
- The `sensor-overlay` Latest scenario runs a daily view over 2026-05-01..06-15. It runs only for stations with the `sensor-change` role (`onlyRoles`), i.e. acebento.

## Station matrix

`stations.json` is generated by `node scripts/fidelity/select-stations.mjs [--refresh]` and committed. It reads `/stations`, `/config/{s}` (instruments, `date_end`, `outage_ranges`), `/deployments/{s}` (the camera model is only there, type "IP Camera") and `/photos/` (slow, about 25–80 s). Each station records the roles it covers and why it was chosen. Responses are cached for 7 days under `DIR/_cache`.

## Legacy shim (local legacy on mesonet2)

The shim lives on the local branch `audit/legacy-shim`, which is never merged or pushed. It makes these changes:

- `app/mdb/utils/params.py`: `API_URL = os.getenv("MESONET_API_URL", "https://mesonet.climate.umt.edu/api/")`
- `app/mdb/utils/get_data.py`: `premade` is dropped from all three requests (`get_station_record`, `get_sat_compare_data`, `get_derived`).
- Shim 2 (`dfa6cb0e`):
  - The mesonet2-only element `ppt_corrected` is excluded from `elements_df`.
  - The `provisional` and `obs_count` columns are dropped from responses.
  - `MESONET_LEVEL=2` sends `level=2` on observations, derived and latest requests. This is like-for-like with the new app's default (level 2 is an intentional divergence; prod legacy uses level 1).

For UI comparisons (Wave 3.5 onward), start local legacy with `MESONET_LEVEL=2` and run with `--legacy localLegacy`. `QC_LEVEL` in `config.mjs` (env `FIDELITY_LEVEL`, default 2) sets the level for `ag`'s `/derived` and for the new-app Downloader `qc`.

Setup (uv; `app/uv.lock` targets Python ≥3.13 but `pyproject.toml`/Dockerfile use 3.11 + poetry):

```sh
git worktree add ../legacy-shim audit/legacy-shim      # or: git archive audit/legacy-shim app | tar -x -C DEST
cd DEST && cp <repo>/mt_counties.geojson .            # plotting.py reads parents[3]/mt_counties.geojson
uv venv -p 3.11 .venv
# poetry.lock -> pinned requirements (one name==version per [[package]]), minus windows-only
# pywin32/pywinpty and mt-mesonet-satellite (its git main now pins setuptools>=80.9 which conflicts):
uv pip install -p .venv/bin/python -r requirements.txt
uv pip install -p .venv/bin/python --no-deps "mt-mesonet-satellite @ git+https://github.com/colinbrust/mt-mesonet-satellite.git"
cd app && MESONET_API_URL=https://mesonet2.climate.umt.edu/api/ \
  ../.venv/bin/gunicorn -b 127.0.0.1:8050 --threads 10 --timeout 180 mdb.app:server
```

Neo4j env vars (`Neo4jUser`/`Neo4jPassword`/`Neo4jURI`) are only needed for the Satellite tab, so they are skipped. Without `ON_SERVER` the app is served at `/`, so station deep links are `http://127.0.0.1:8050/<station>/`.

Known shim-on-mesonet2 artifacts without shim 2. These come from the API's response shape, not from the shim:

- mesonet2 has a new element `ppt_corrected` ("Precipitation (fill-corrected)"; NULL inside high-wind events, with the event total at the end). Legacy builds its element list by substring from `{API}elements` (`app.py:850-851`, `utils/params.py:24`), so on mesonet2 it also requests `ppt_corrected`. `filter_df("Precipitation")` then keeps both columns, and `plot_ppt` plots the last one (`utils/plotting.py:741`). So local legacy plots the fill-corrected series, not raw `ppt`, which shows up as trailing nulls versus prod. With gridMET on, `merge_normal_data("Precipitation (fill-corrected) [in]")` has no normals mapping and returns `None`, and `add_boxplot_normals` raises `AttributeError` (`utils/plotting.py:686`). Local legacy therefore cannot render "Daily + gridMET" on mesonet2.
- mesonet2 also appends `provisional` (and `obs_count` with `na_info`) columns that the prod API doesn't send.
- mesonet2 `/api/photos/{s}/{dir}?dt=` (unversioned, without `force`/`web`) returns JSON, which the browser blocks (ERR_BLOCKED_BY_ORB). The local legacy photo card is therefore broken.

## Files

- `config.mjs`: targets, URL builders, scenarios, tolerances, timeouts.
- `select-stations.mjs` → `stations.json`: the station matrix.
- `lib/browser.mjs`: page instrumentation (console, network, settle) and the in-page extractor (Plotly `gd.data`/layout, tables, cards).
- `lib/drivers.mjs`: legacy and new-app scenario drivers, Dash `setProps`, Downloader flows.
- `lib/compare.mjs`: trace matching and numeric diff, text/kv card diff, CSV diff.
- `lib/api-parity.mjs`, `lib/derived.mjs`: API-level comparisons.
- `lib/report.mjs`: `report.html`.
- `CHECKLIST.md`: the legacy feature inventory (file:line, automatable or manual, status column).
